The provider removes identity162from purchases and removes identity-bearing event records in one transaction.163A repeated request returns the same completed job, including after restart.164 165The app owns already-delivered copies: it erases its receiver inbox and retains166a keyed deletion marker so late signed events are acknowledged without storing167the deleted identity. The example also refuses rebinding erased evidence.168This is a local ownership policy; the protocol does not cancel the store subscription.169Database backups and the app’s own account records remain the operator’s responsibility.170 171Run `bun verify-erasure.mjs` to exercise deletion while a delivery is in flight,172late lifecycle events, repeated requests, and storage reopening.173 174## Replace the example with IAPKit175 176The OpenIAP checkout includes `packages/kit/scripts/docs/run-commerce-interop.mjs`.177It starts IAPKit with an isolated local Convex deployment and keeps one app178backend and receiver running while switching the commerce provider. See the179[composition guide](https://openiap.dev/commerce-protocol/ecosystem#composition-proof)180for the executed report, source, and command. No IAPKit account or store keys are needed.181 182## What remains for production183 184Real store validation and sandbox purchases, login, tenant185isolation, GraphQL, public HTTPS delivery protections, and operational recovery186are not implemented here.
